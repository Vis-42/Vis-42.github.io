# Website — parthbhargava.net

Hugo static site, no theme, no framework (Hugo 0.167). This file is the reference for the site's content and design. How to build the notebooks, sync lab reports and publish is in `GUIDE.md` at the repo root.

```bash
hugo server        # preview at localhost:1313
hugo --minify      # check a production build
```

`public/` is build output and is never committed. The live site is built by the GitHub Action on `Vis-42/Vis-42.github.io`.

---

## Where things live

| Path | What it is |
|---|---|
| `layouts/_default/baseof.html` | the whole design: one `<style>` block, the margin nav, mobile menu, footer and scripts. Don't add a separate stylesheet. |
| `layouts/_default/home.html` | homepage hero card and sticker field |
| `layouts/<section>/list.html`, `single.html` | each section's pages |
| `content/_index.md` | homepage "about" text |
| `content/<section>/_index.md` | section page; its `filed:` sets the small label above the heading |
| `data/coursework.toml` | the `/coursework/` courses and reports, and the `~/-uni` PDFs behind them |
| `static/apps/` | exported marimo notebooks + shared frontend (generated by `py/build.py`) |
| `static/pdfs/experiments/`, `data/coursework-sources.json` | published reports, and their titles and page counts (generated by `sync_uni.py`) |
| `static/media/thumbs/`, `static/media/photos/` | thumbnails, photographs (+ `photos/thumbs/`) |
| `static/stickers/svg/` | homepage doodles |

Listings build themselves: `/explorations/` from each exploration's front matter, `/blog/` and `/photographs/` from their pages, `/coursework/` from `data/coursework.toml`. Nothing is kept in sync by hand.

## Content types

### Exploration

`content/explorations/<slug>/index.md`. The body is Markdown; its first 30 words are the card summary on `/explorations/`.

```yaml
---
title: "Exploration Title"
slug: "<slug>"
weight: 14          # ordering; higher = further down
thumb: "/media/thumbs/<slug>.jpg"
filed: "Topic · subtopic"
app: "/apps/<slug>/"   # the notebook; also how py/build.py and deploy-public.sh find it
links:
  - label: "Notebook source (Python · marimo)"
    url: "https://github.com/Vis-42/Vis-42.github.io/blob/main/py/<slug>/<slug>.py"
  - label: "Original Julia notebook (upstream)"
    url: "https://github.com/Vis-42/Vis-42.github.io/tree/main/jl/<slug>"
---
Description paragraph here.
```

Thumbnails are JPEGs under 200 KB at `static/media/thumbs/<slug>.jpg`.

### Project

`content/projects/<slug>/index.md`, same front matter. `layouts/projects/list.html` is still a "nothing here yet" placeholder that doesn't list pages, so when the first project lands, give it a card grid like `layouts/explorations/list.html` and drop the "· soon" greying of its nav link in `baseof.html`. `build.py` and `deploy-public.sh` only look for notebooks under `content/explorations/`.

### Blog post

`content/blog/<slug>/index.md`; listed newest first. Draft revisions saved beside it as `v1.md`, `v2.md`, ... are never published.

```yaml
---
title: "Title of the post"
date: 2026-10-09
excerpt: "One or two sentences shown on the /blog/ listing page."
tags: ["optional", "tags"]
---
```

### Photograph

Image at `static/media/photos/<filename>.jpg`, a 600 px thumbnail at `static/media/photos/thumbs/<filename>.jpg`, and `content/photographs/<slug>.md`:

```yaml
---
title: "Short label"
date: 2026-10-09
src: "/media/photos/<filename>.jpg"
caption: "what it shows · place, year"
---
```

### Coursework report

`/coursework/` is an arXiv-style listing grouped by course: each entry is `[n] [pdf, slides]`, the title, `Comments: N pages` and a one-paragraph summary. No thumbnails, no code links. Add a `[[reports]]` entry to `data/coursework.toml`:

```toml
[[reports]]
slug = "<slug>"                                   # URL: /pdfs/experiments/<slug>.pdf
report = "Sem5_exchange/<course>/<expt>/report/report.pdf"   # path inside ~/-uni
slides = "Sem5_exchange/<course>/<expt>/presentation/slides.pdf"   # optional
summary = "One or two sentences: what was measured and the result."
```

The report appears under the `[[courses]]` entry whose `folder` its path starts with, in file order; a new course needs a `[[courses]]` entry (`folder`, `code`, `name`, `term`), placed where it should appear (newest first). The title and page count come from the PDF itself (Typst sets the title from the document), so give `title = "..."` only for a PDF without one. `sync_uni.py` copies the committed PDFs to `static/pdfs/experiments/<slug>.pdf` and `<slug>-slides.pdf`, scaling oversized photos down to 2000 px (text, vector figures and links untouched), and deletes PDFs there that no entry lists.

## Stickers

SVG doodles in `static/stickers/svg/` are CSS mask-image glyphs on the homepage, drawn in the page's accent colour in both themes. To add one, put the SVG there and add a `<figure class="sticker line">` block in `layouts/_default/home.html` like the existing ones: `data-rot` is the tilt in degrees, `style` sets position and size.

## If something doesn't update

- A PDF or image returns 404: check the file is committed and the path matches exactly (case-sensitive on the server).
- A notebook doesn't load: `static/apps/<slug>/index.html`, `static/apps/assets/` and `static/apps/_shared/canvas.html` must all exist; rebuilding with `py/build.py` restores them.
- The site doesn't update after publishing: check the Action on `github.com/Vis-42/Vis-42.github.io/actions`, and that Pages is set to deploy from **GitHub Actions**.
